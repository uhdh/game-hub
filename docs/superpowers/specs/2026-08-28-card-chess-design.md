# 카드체스 (Card Chess) — 설계 문서

## 개요
5×5 보드 위에서 플레이어와 AI가 각자 말 5개를 놓고, 매 턴 자기 앞에 놓인 카드 2장 중 하나를 골라 그 카드의 이동 규칙대로 말 1개를 움직이는 1인 vs AI 보드 게임. 카드는 5종류뿐이며 사용한 카드는 대기존으로 가고 대기존 카드가 손으로 들어오는 순환 구조라, 어떤 카드가 누구 손에 있고 다음에 무엇이 들어올지는 항상 양쪽 모두에게 공개된 정보다(히든 정보 없음, 완전정보 게임).

기존 프로젝트 컨벤션을 따른다: 다크 테마, `index.html` GAMES 배열에 카드 추가, Supabase(`paktzmofotvwfdxcpmzv` 프로젝트) REST API를 raw fetch로 사용, 랜덤 닉네임 자동 배정 패턴 재사용. 단, 이 게임은 규칙 엔진과 미니맥스 AI가 이 프로젝트의 다른 게임들보다 촘촘해서 `gomoku-board.js`/`gomoku-ai.js`처럼 로직을 별도 파일로 분리하고 단위 테스트를 붙인다.

## 파일 구성
- `card-chess.html` — 게임 본체(신규): UI 렌더링, 입력 처리, Supabase 연동, 시작 화면
- `card-chess-engine.js` — 게임 규칙 엔진 + 미니맥스 AI(신규, UMD 모듈로 `gomoku-ai.js`와 동일한 로드 방식)
- `card-chess-engine.test.js` — 규칙 엔진/AI 단위 테스트(신규)
- `index.html` — GAMES 배열에 새 카드 추가

## 보드 & 좌표계
- 5열(col 0~4) × 5행(row 0~4). 왼쪽 플레이어(P1, 사람 또는 AI)는 col 0 전체(5칸)에 말 5개를 놓고 오른쪽(col +)을 바라봄. 오른쪽 플레이어(P2)는 col 4 전체에 말 5개를 놓고 왼쪽(col -)을 바라봄.
- 각 말은 `facing: +1 | -1`(전진 방향, col 증감)을 갖는다. 말이 이동해서 반대쪽 끝 열(자기 시작열이 아닌 열, 즉 col 4 또는 col 0)에 도달하면 그 즉시 `facing`이 반전된다. 이동 방향 자체는 그대로 전진1로 이동한 결과이며, 반전은 그 다음 턴부터 적용된다. facing은 어태커 카드의 "전진"/"대각선-전진" 판정에만 쓰인다(다른 카드는 무관).
- 각 플레이어의 **성(castle)**: 상대 시작열의 3행(가운데 칸) — P1의 성은 `(col 4, row 2)`, P2의 성은 `(col 0, row 2)`. 시작 시 그 칸엔 이미 그 진영 자신의 말이 서 있다.

## 카드 5종 이동 규칙
공통: 이동 목적지가 보드 밖이면 그 방향은 무효. 목적지에 자기 말이 있으면 무효(자기 말 위에는 못 감). 목적지에 상대 말이 있으면 그 말을 포획하고 그 칸으로 이동. "넘을 수 없다"고 명시된 카드는 경로 중간 칸에 다른 말(내 말/상대 말 모두)이 있으면 그 방향 이동 자체가 막힌다.

| 카드 | 이동 |
|---|---|
| 록 | 상하좌우 1칸 |
| 비숍 | 대각선 4방향 1칸 |
| 어태커 | 전진(facing 방향) 1칸 또는 2칸(직선, 중간에 다른 말 있으면 막힘 — 넘기 불가) · 또는 대각선-전진 좌/우 1칸(전진 방향 기준 앞쪽 대각선 두 칸만, 뒤쪽 대각선 불가) |
| 나이트 | 직선 2칸(상하좌우 중 하나) + 그 끝에서 수직 방향 1칸 → 총 8개 후보 지점. 경로 중간에 다른 말이 있어도 넘어갈 수 있음 |
| 점퍼 | 인접 8칸(상하좌우+대각선) 중 말이 있는 칸이 있으면, 그 방향으로 정확히 2칸 뛰어 착지(중간에 넘은 말은 포획되지 않고 그대로 남음). 인접 8칸에 말이 하나도 없으면 점퍼 카드로는 그 말을 움직일 수 없음. **보드 위 전체 말 수가 2개(양측 합산)가 되는 순간, 점퍼 카드는 그 즉시 그리고 영구히 퀸 카드로 취급**(카드 이름/규칙이 남은 게임 내내 퀸으로 고정, 되돌아가지 않음) |
| 퀸 | 상하좌우+대각선 8방향 1칸 |

카드는 물리적으로 5장뿐(각 1장씩)이며 게임 중 개수가 늘거나 줄지 않는다.

## 턴 진행

### 초기 셋업
1. 선(먼저 움직이는 쪽)/후(드래프트 주도하는 쪽) 무작위 결정(50:50).
2. 후공이 5장 중 2장을 자기 앞에 배치.
3. 후공이 남은 3장 중 2장을 선공 앞에 배치.
4. 남은 1장은 대기존.
5. 사람이 후공이면 카드 선택 UI(5장 중 2장 클릭 → 남은 3장 중 2장 클릭)를 보여준다. AI가 후공이면 AI가 즉시 드래프트를 수행한다(아래 "AI 드래프트 로직" 참고).

### 매 턴
1. 현재 차례 플레이어는 자기 앞 카드 2장 중 하나를 선택.
2. 그 카드의 이동 규칙으로 합법 이동이 하나라도 있는 자기 말 중 하나를 선택하고, 목적지를 선택해 이동(포획 포함 처리).
3. **이동 가능한 칸이 전혀 없는 경우**(그 카드로 움직일 수 있는 말이 아예 없음): 그래도 그 카드를 "사용한 것"으로 처리하고(말은 그대로) 턴을 넘긴다. 대기존 교체는 정상 진행(아래 4번).
4. 사용한 카드는 대기존으로, 대기존에 있던 카드는 이번에 카드를 쓴 플레이어 앞으로 이동.
5. 턴 종료 시점에 아래 "승리 판정"을 확인 후, 게임이 끝나지 않았으면 상대 차례로 전환.

### 턴 시작 시 승리 판정
자기 턴이 시작될 때: 직전 자기 턴이 끝난 시점에 상대의 성 칸에 자기 말이 있었고, 그 사이 상대 턴이 그 말을 제거하지 못한 채 끝났다면(=지금도 그 칸에 자기 말이 그대로 있으면) 그 자리에서 즉시 승리. 이 판정은 카드를 고르기 전에 먼저 수행한다.

성 칸 점유는 "포획으로 들어가든(원래 있던 상대 말을 잡음) 빈 칸으로 걸어 들어가든(상대가 미리 비켜서 놓은 경우)" 상관없이 자기 턴이 끝난 시점에 그 칸에 자기 말이 서 있기만 하면 카운트를 시작한다.

### 종료 조건
1. 상대 말이 모두 제거됨 → 즉시 승리.
2. 위 "턴 시작 시 승리 판정" 충족 → 즉시 승리.

## AI 설계

### 드래프트(선/후 무관하게 AI가 카드 배분을 맡을 때)
간단한 휴리스틱: 나이트·퀸(또는 퀸으로 전환 전 점퍼)처럼 이동 범위가 넓은 카드를 자기 앞 2장으로 우선 선택하고, 상대에게는 상대적으로 제한적인 카드(록/비숍처럼 단거리 카드)를 우선 배정한다. 완벽한 최적화보다 "AI가 성의없이 배분하지 않는다" 정도의 수준이면 충분 — 미니맥스 탐색이 실제 실력을 담당하므로 드래프트 단계는 가벼운 휴리스틱으로 처리.

### 수 탐색: 미니맥스 + 알파-베타 가지치기
- 완전정보 게임이므로(양쪽 손패/대기카드 모두 공개) 표준 미니맥스 그대로 적용 가능.
- 탐색 깊이: 4플라이(자신 2수, 상대 2수) 고정. 5×5 보드 + 카드 2장×말 최대 5개 조합이라 한 노드당 합법 수가 대략 10~40개 수준 — 알파-베타로 이 깊이는 즉시(수십~수백ms) 계산 가능.
- 매 노드에서 먼저 "이 수로 즉시 승리(전멸 또는 성 점유 후 판정 조건 충족)"인지 확인해 종료 노드는 ±∞로 조기 반환.
- 평가 함수(자기 시점 기준 가중합):
  - **말 수 차이**(자기 말 수 − 상대 말 수) × 100 — 가장 큰 가중치.
  - **성 접근도**: 자기 말 중 상대 성까지 최소 거리(체비셰프 거리) × −5(가까울수록 유리). 상대 말도 대칭으로 반영.
  - **성 점유 보너스**: 자기 말이 상대 성 칸에 서 있으면 +50(이미 승리 판정을 통과한 상태가 아니라 "아직 상대가 한 턴 남은" 상태에서도 강하게 선호하도록).
  - **기동성**: 다음 자기 턴에 손에 있(게 될) 카드 2장 기준 총 합법 수 개수 × 1 (약한 가중치).
- 동점 후보가 여럿이면 무작위로 하나 선택.
- AI 턴 실행 시 UI에는 "AI가 생각하는 중..." 표시 후 0.5~1초 지연 뒤 자동 실행(지각변동 AI와 동일 패턴).

### 규칙 엔진 API (`card-chess-engine.js`, UMD)
순수 함수 위주로 구성해 테스트하기 쉽게 만든다. 대략:
- `createInitialState({ firstPlayer })` — 보드/말/카드 배치 포함 초기 상태 생성(드래프트 이전 단계는 별도 헬퍼로 분리: `draftCards(...)`).
- `getLegalMoves(state, cardId)` — 그 카드로 가능한 `{ from, to }` 전체 목록.
- `applyMove(state, cardId, from, to)` — 이동 적용 + 카드 순환 + 포획 + facing 반전 처리 + 성 점유 상태 갱신 → 새 state 반환(불변 갱신).
- `checkWinner(state)` — 턴 시작 시 승리 판정 포함한 현재 상태의 승자(`null | 'P1' | 'P2'`).
- `chooseAiMove(state, depth)` — 미니맥스 실행 후 `{ cardId, from, to }` 반환.
- `chooseAiDraft(state)` — AI가 후공일 때 드래프트 수행.

## 닉네임 & Supabase 기록

### 시작 화면
사람(항상 존재) 닉네임 입력란 1개. 비워두면 기존 랜덤 닉네임 규칙(`이름#숫자`, 다른 게임과 동일한 이름 풀) 자동 배정 + localStorage(`cardChessNickname`)에 마지막 값 기억.

### `card_chess_leaderboard` 테이블 (신규)
`gomoku_extreme_ranking`과 동일한 구조로 통일:

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | uuid/serial (PK) | |
| nickname | text | |
| rating | integer | 기본값 1200, Elo 계산 |
| wins | integer | |
| losses | integer | |
| updated_at | timestamptz | |

Elo 계산은 `gomoku-rating.js`와 동일한 공식(`1/(1+10^((aiRating-playerRating)/400))`, K-factor)을 `card-chess-engine.js` 안에 직접 인라인으로 넣는다(파일 하나 늘리기엔 너무 작은 로직 — 게임마다 갈라 쓰는 기존 방식 유지). AI 고정 레이팅 값은 구현 시 적당히 정함(예: 1500).

RLS: anon insert + select + update(자기 레이팅 갱신)만 허용, 다른 게임 리더보드 테이블과 동일 패턴.

### 홈 리더보드 연동
`index.html`의 `LB_SECTIONS`에 항목 추가:
```
{
  label: '카드체스',
  fetch: (limit) => fetchSimpleTop('card_chess_leaderboard', 'nickname,rating,wins,losses', 'rating.desc', limit),
  format: r => `${r.wins}승 ${r.losses}패 · ${r.rating}점`,
}
```

## UI 화면 구성
1. **시작 화면**: 타이틀 + 규칙 요약 + 닉네임 입력란 + "게임 시작" 버튼.
2. **게임 화면**:
   - 상단: "← 게임 허브" 링크 + 타이틀 + "새 게임" 버튼.
   - 좌/우 카드 슬롯: 각 플레이어 앞에 카드 2장(항상 공개), 가운데 위/아래에 대기존 카드 1장 표시(레퍼런스 이미지 레이아웃 그대로 — 좌 플레이어 카드, 중앙 보드, 우 플레이어 카드, 상단 대기존).
   - 5×5 보드: 말 아이콘(방향 표시), 성 칸은 별도 표식(테두리나 배경색으로 항상 표시), 선택한 말의 합법 목적지 하이라이트.
   - 상태 바: 현재 차례, AI 사고 중 표시.
   - 조작: 카드 클릭 → 그 카드로 이동 가능한 자기 말 하이라이트 → 말 클릭 → 목적지 하이라이트 → 목적지 클릭으로 이동 확정. 이동 가능한 말이 하나도 없는 카드를 클릭하면 확인 후 바로 턴 소모(패스) 처리.
   - 규칙 요약 박스(카드별 이동 규칙 간단 정리, 하단 상시 노출).
3. **승리 모달**: 승자 표시(사람 닉네임 또는 "AI") + 승리 사유(전멸/성 점령) + "새 게임" 버튼. 사람이 이겼을 때만 Elo가 오르고 리더보드에 반영됨을 별도 안내하지 않음(조용히 처리, 다른 게임과 동일).
4. 홈(`index.html`)에 새 게임 카드 추가: 이름 "카드체스", desc는 구현 시 확정(예: "카드로 말을 움직여 상대의 성을 점령하세요"), 아이콘은 `emoji` 방식(예: ♟️ 또는 🃏) — 카드+말 조합이라 새 아이콘 타입을 만들 필요는 없음.

## 범위 밖 (Out of scope)
- 로컬 2인 동시 플레이(같은 기기 턴 교대) — vs AI만 지원.
- 온라인 실시간 매칭(P2P) — 지원하지 않음.
- AI 난이도 다단계 — 미니맥스 깊이 4 고정 하나만.
- 무승부 처리 — 이 게임 규칙상 무승부가 날 수 없다고 가정(말이 있는 한 항상 최소 하나의 카드로는 턴을 진행할 수 있고, 승리 조건은 전멸/성점령뿐이라 이론상 게임이 영원히 안 끝나는 경우는 배제하지 않았음 — 실제로 무한 루프가 관측되면 후속 작업에서 수 반복 감지/무승부 규칙을 추가한다).
- 리플레이/기보 저장 — 승패 결과 1건만 기록.
